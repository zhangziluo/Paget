# Paget

A desktop reader with its own Python kernel (`core/`): Tauri v2 + React/TS shell.

内核**就在这个仓库里**（2026-10-11 起）：克隆一个仓库就能跑、能打包，不需要第二个 checkout。
这个目录是用户本机的图形界面，不是要发布的包。

## 它到底在做什么

```
┌────────────────┐   invoke    ┌──────────────────┐   stdin/stdout    ┌───────────────────────┐
│ React (src/)   │ ──────────▶ │ Rust (src-tauri) │ ─── 一行一个 JSON ──▶│ python -m wreader.serve│
│ 书架 / 阅读页  │             │ core_client.rs   │ ◀───────────────── │ 数据目录（权威）        │
└────────────────┘             │ db.rs (SQLite)   │                    └───────────────────────┘
                               └──────────────────┘
```

- **数据只有一份**：书库、阅读位置、时长、统计、成就全都由 Python 内核写在一个数据目录里
  （纯文本 JSON/TOML），界面每一处读的都是它 —— 关掉再打开、清掉缓存都接着上次的位置。
  那个目录**跟着「谁在跑」分两档**（2026-10-14 定，见「打包」那一节）：`npm run tauri dev` 跑的是
  项目里的 `<repo>/.wreader/`；**装出去的 app** 跑的是应用数据目录 ——
  macOS `~/Library/Application Support/com.paget.gui/core`、
  Windows `%LOCALAPPDATA%\com.paget.gui\core`。换一版、换台机器、把源码树挪个地方，用户的书都还在
  原地；升级第一次跑时，老位置（项目 `.wreader/` 或 `~/.wreader`）那份会**复制**过来。
  （从前发布版也会按**编译期路径**去找数据 —— 于是同一台机器上编译出来的包会把书库写进那个
  checkout 的 `.wreader/`，换一次源码位置或换个目录打包，装上新版看着就像「书全被删了」。）
- **SQLite 只是缓存**：`db.rs` 里那个 `cache.sqlite3`（放在应用配置目录）存的是书架快照、
  全文索引和界面自己的设置，随时可以删，删了下次启动从内核重建。
- **界面不重写任何规则**：进度百分比用 `library.position_percentage` 的算法、
  时间戳用内核的"本地时间 + 秒级"格式、行区间交给内核去重，界面只负责画。

## 跑起来

```bash
# 前置：内核已经装进它自己的 venv（见 core/README.md），也就是
#   core/.venv/bin/python -m wreader.serve 能跑
npm install
npm run tauri dev        # 开发（前端热更新 + Rust 侧自动重编）
packaging/build-core.sh  # 冻结内核（打包前必须先跑一次）
npm run tauri build -- --ignore-version-mismatches   # 打包成 .app / .dmg
```

内核怎么被找到（`core_client.rs` 的 `CoreCommand::resolve`，按顺序）：

1. `$PAGET_CORE_COMMAND` —— 整条命令行，例如 `paget-core --stdio`；
2. `$PAGET_CORE_PYTHON` —— 指定解释器；
3. 自动：**随包内核**（`<resource dir>/core/paget-core`，或与主程序并排的同名文件；
   只在 release 构建里认它 —— 否则 `tauri dev` 会拿旧的冻结点盖住 `core/` 的修改），
   然后是仓库自带的 `core/.venv/bin/python`；
4. 兜底 `python3`（要求 `wreader` 已装进那个解释器）。

### 首屏写着「core transport failed: the core exited without answering」

内核**根本没起来**。这句话现在会连**整条命令**和**内核自己那句 stderr** 一起报出来，照着看就知道
是哪一步不对（最典型的是 `ModuleNotFoundError: No module named 'wreader'` —— 探到的那个解释器里
没装内核）。三种修法，任选一种：

```bash
# ① 把内核装进它自己的 venv（就在仓库里）
core/.venv/bin/python -m pip install -e core

# ② 指定一个装了内核的解释器（比自动探测优先）
PAGET_CORE_PYTHON=/path/to/python npm run tauri dev

# ③ 手头没有内核源码时，用随包那份冻结点顶一下（功能一样，但改内核源码不再生效）
PAGET_CORE_COMMAND="$PWD/src-tauri/binaries/paget-core/paget-core" npm run tauri dev
```

> 为什么开发构建不肯自动退回随包内核：`tauri dev` 会把冻结点拷到调试产物旁边，一旦拿它当内核，
> `core/` 里的改动就全被旧二进制盖住了（`auto_command_with` 的注释）。所以这条路只能
> **显式**走，也就是上面的 ③。

## 界面做了什么

没有标签栏：**书房本身就是首页**，所有功能都藏在墙上那几枚便利贴里，点开才展开成一整页，
右上角有「← 返回书架」。每一页都只调内核的对应方法，自己不重算任何规则：

- **书房（书架）**：整间屋子锁在一屏内，不出现滚动条 —— 书多到一屏放不下时，
  鼠标靠近窗口左右两侧才会浮现 **‹ ›** 翻页箭头，点它切换下一屏。
  排布是「**一排一格**」：
  **主屏**是书房全景 —— 最上面一栏并排着三枚**便利贴**与一枚**数字时钟**：便利贴上写的是
  生活化的字（**「日记」** = 统计、**「勋章」** = 成就、**「调一调」** = 设置 / 数据 / 已归档），
  和纸质感（字是系统手写体栈，`0.72rem` 加粗、深墨 —— 小纸片上也一眼读得清）、
  米黄 / 淡粉 / 淡绿三色，各自歪 ±3°，**能拖到任意位置**（松手吸附、位置记在本机）；
  时钟纯展示、不可点；最右是重新同步 / 清空缓存 / 放大镜三个小圆钮；
  下面是一组两层的架子：**上层只放装饰**（留声机、靠在留声机木箱侧面的一叠黑胶唱片、收音机 —— 都不可点，
  为以后的音频播放留个位置；外加**毛绒玩偶**：兔子 / 猫头鹰 / 乌龟**三只可以同时摆上**，
  点那一格弹出的小面板里**逐只**决定放不放（**整行**点一下就放上 / 取下，缩略图 + 名字
  就是那一行；三只玩偶都只有**正面**一种造型），摆法记在本机，下次打开还是你摆的样子，
  **摆上两只以上**时面板里还多一行**「间距」**（一根滑杆：往左挤紧、往右分开，出厂是轻轻搭在一起那一档 ——
  间距也记在本机，与摆法分开存）；
  一只也没摆时那格留一个虚线的「＋」；**下层只有一排书**（这一排的头一格是一只**藤条篮子**（篮子里插着一本书、几张残页，点它就是导入电子书；Windows / Linux 上按一次会先问「文件还是文件夹」—— 那边的系统对话框不能同框多选））。
  两层之间、以及这排书下面，各是**一道白色带阴影的挡板**（书就站在挡板上）。
  这四层（窗 / 那一栏 / 摆件架 / 那一排书）**各占自己该占的高度**，留白落在书架**下面**：
  底座下面透出一整片墙面、挡板往下投一道更实的影 —— 书架看起来是**悬在墙上**的，
  而不是贴着地板站住（窗也就着这点余量加高了一档；分屏信息沉到屏幕底部当页脚，不切碎那片留白）。
  **从第二屏起是一整面书架**：窗与墙上那一栏都收起来，**三排书**顶到最上面，每排下面同样垫一块
  白色挡板；右上角浮一枚 **⌂ 回到主屏**（主屏上不显示它），书**超过三屏**时它旁边再多一个
  「跳到第几屏」的输入框（填数字回车或点「跳转」直达；主屏上这一份挂在墙上那一栏的右端）。
  **翻屏**：鼠标贴到窗口左右两侧会浮现 **‹ ›** 箭头；更省事的是**键盘 `←` / `→`** ——
  主屏按 `→` 去第二屏、第三屏……，`←` 往回，已经在头 / 尾就停在原地（不吞按键）。
  这两个键**只在书架页生效**：进了阅读页，`←` / `→` 是「滚一屏」。
  **每本书的书脊厚薄由内核记的总字数算**（对数曲线：三万字以下一律保底 4.2rem、一百二十万字
  以上封顶 7.6rem，见 `lib/shelfLayout.ts`）—— 几百字的短篇不会薄成一片纸，百万字长篇也不会
  占掉半条书架。**一排摆几本按厚度一本本累加**（窗口宽度用 `ResizeObserver` 量），
  所以「一屏多少本」是排出来的结果：书越厚，一屏摆得越少、页数跟着变，错落得像真书架。
  书脊上的书名一长，**字号就自动缩**（保证整条排下、不截断），厚书只是侧边留白更宽、侧影更深
  （夜里跟着整间屋子的光照再深一档）；字数没统计出来的（解析失败 / 空文件）按最薄一档摆。
  想要整齐划一的话，**设置 →「书架的样子」→「书脊厚薄跟着字数走」**关掉就是全体等宽、平分每一排
  （这一项存本机 `gui_settings`，不进内核）。
  便利贴鼠标移上去会**微微下压、投影加深、右下角那点翘起展开**；点一下它「**撕下来**」
  （向上飞出、转 15° 淡出）再打开对应那一页，关掉那一页时它**从上方贴回原处**；
  连点 5 下会**翻到背面**给你一句闲话（22:00 之后纸边发黄）。
  书脊上的书目、进度条和百分比都来自内核 `list`，先画缓存再同步
  （行号 / 字数 / 累计时长 / 上次阅读这些细节搬进了下面的右键菜单）。
  搜索是**纯前端**的：点右上角的 🔍（或按 `/`、`⌘K`）会给整片书架铺一层
  `backdrop-filter: blur(8px)` 遮罩、并从顶部滑下输入框，输入即时按**书名 / 作者**过滤身后的书架；
  回车确认后遮罩收起、命中的书脊高亮 2 秒自动落掉，Esc 或点遮罩空白处取消。
- **书架管理模式（右上角那把锤子🔨）**：点一下进 / 出（进入时书架轻轻一震、往下一沉，
  最下面浮出一条管理条）。里面两件事：**拖着书排序**（按住书脊挪过 4px 才算拖：被拖的那本浮起来、
  放大到 1.1 并投下一道影，落点两侧的相邻两本被挤扁成 `scaleX(0.8)`，松手后弹性回弹；
  原位先留空，只留一张半透明的缩略图）、**点一下选中、用键盘排序**（见下）。
  **跨屏**：把书拖到屏幕左 / 右边缘 **停留 0.3 秒**（或按 `←` / `→`）就翻一屏，
  可以一路拖到别的屏；`Esc` = 放回原处。
  **落位记的是「这一本前面」**（用的是**书 id** 而不是「第几格」）—— 书脊厚度按字数算、
  一排放几本按窗口宽度算，挂在格子上必然错位。
  **键盘排序**（不用拖）：**点一下**书脊就把它选中 —— 书脊抬起来、圈一圈暖色描边，
  管理条上写着「已选中「书名」」并多一枚「取消选中」；接着用 **`←` `↑` 往前一位、
  `→` `↓` 往后一位**（书架横着排，上下与左右同义），挪出这一屏会自动翻屏跟着它，
  `Esc`（或再点它一下）放开 —— 放开之后 `←` / `→` 才又是翻屏。
  **玩偶也会看热闹**：进模式时兔子抬头张望、乌龟把脑袋缩进壳里、猫头鹰左右张望；
  拖着书从它头顶过，兔子会跳起来拦一下（架子上摆着的几只**各演各的**，一只也没摆就没人理你
  —— 摆件架那三只怎么摆见上面「上层只放装饰」那段）。**书的先后存内核**（`~/.wreader/shelf.json`，
  与书库并排：换机器 / 备份 / 清掉缓存看到的都是同一份；渲染时再按书 id 与内核书单
  并一次，删掉 / 封印掉的书自动消失），所以下次打开还是你摆的样子 —— 管理条右边那枚
  「内核 / 本机」小标签写着这份布局存在哪儿（**老内核**还不认识这两个接口时，会自动把布局
  留在本机设置里，功能一样不少）。
  **批量编辑**（管理条上的 `☑️ 批量编辑`）：点进去每根书脊右上角冒出一个勾选圈，点一下勾上
  （选中那本会抬起来、圈一圈暖色），可以**跨屏多选**；管理条随之换成
  **全选 / 清空 + 改书名 / 标记已读·未读 / 删除**：
  - **批量改书名**：弹窗给四条规则 —— **前缀 / 后缀**（拼在每本书名首尾）与**查找 / 替换**
    （按字面替换，不是正则），并拿选中的第一本**实时预览**改完的样子；保存走内核 `set_meta`，
    正文、进度与时长一概不碰（把书名改空的那些会跳过并记下来）。
  - **改阅读状态**：`标记已读` / `标记未读` 走内核 `finish`（阅读进度不删）。
  - **批量删除**：再确认一次后一本一条地删（内核 `remove`），进度写在书架上
    （「正在删除第 3/10 本」），某一本失败不影响其余，最后回执里列出失败的几本。
  `返回排序`回到拖拽排序，`完成`退出管理模式（勾选一并清空）；老内核探不到
  `set_meta` / `finish` / `remove` 时，对应按钮**禁用并说明原因**。
- **键盘**：`M` 进 / 出管理模式、`S` 统计、`A` 成就、`G` 设置（「调一调」那一页，**并把页签拨回
  「设置」**）—— 四个键都是「去哪儿」，**回程按 `Esc`**（三个页的返回按钮上也写着）；
  按 `M` 回书房并**直接进管理模式**；键位表在 `src/lib/shortcuts.ts`（便利贴与锤子的悬停提示里也写着）。
  书架上本来就有 `/` 或 `⌘K` 唤起搜索、`←` `→` 翻屏、`Esc` 关掉搜索。**正在输入框里打字时不抢
  这几个键**（`Esc` 例外 —— 它没有「在输入框里」的语义）；`⌘` / `Ctrl` / `Alt` / `Shift` 的组合键
  一概不碰，留给系统。**管理模式下点中了一件东西**（上面的键盘排序）时，`←` `↑` `→` `↓`
  先归它：那是「挪一位」而不是翻屏 —— `Esc` 放开，翻屏立刻还给 `←` / `→`。
- **书籍右键菜单**：在书脊上点**右键**（触屏**长按 550ms**）弹出浅木色圆角卡片 ——
  **继续阅读 / 阅读统计 / 属性 / 置顶·取消置顶 / 标记已读·未读 / 删除（二次确认）/ 设置限时**。
  菜单在指针处弹出、超出窗口时自动夹回来，点菜单外或按 Esc 关闭，出现时淡入 + 轻微下落 0.2s。
  其中：**置顶**是界面自己的状态（存本机 `gui_settings`，排在书架最前）；
  **阅读统计**来自内核 `get_book`（打卡天数按 `progress.sessions` 里不同的日期数）；
  **属性**列出书名 / 作者 / 标签 / 总字数 / 添加时间 / 最后阅读，其中**前三项可以直接改** ——
  保存走内核的 `set_meta`，写的是同一份 `library.json`（书架与之后打开的每一处立刻看到新名字；
  只改这三项标签，正文文件、章节表与阅读进度一概不动，改名顺手也不会丢进度）。
  **标记已读**与**删除**走内核的 `finish` / `remove`，同样与终端同源。
  后三项只有较新的内核（`remove` / `finish` 自 2026-10-04、`set_meta` 更晚）才有：
  界面启动时会拿一个**不可能存在的 book id** 各探一次
  （`unknown method` = 内核不认识它，`unknown book id` = 认识；探针零副作用），
  探不到就把这两项菜单**禁用**、把「属性」里的编辑框降级成只读清单并说明原因，
  而不是等点了才报错。
- **书架上那只藤条篮子 → 导入电子书**（摆在主屏那一排书的最前面一格，篮子里插着一本书、几张残页）：点一下弹出**系统原生的文件浏览器**，
  选中的每个路径交给内核 `import` 转换入索引（认得的格式全由内核决定：`.txt` / `.epub` / `.mobi` / `.azw3` / `.pdf`，
  面板本身不挡扩展名）。**PDF 是例外，而且是有意的**：它的默认是**图片模式** —— 导入只收文件、数页数、取一张封面
  （几百页的书一两秒），阅读页用 pdf.js 把页面画出来；想读文字，在阅读页按那颗**「转换成文字」**（那一步才抽文字层，
  几万行要几十秒，转完直接进文字阅读页。文字/图片这个看法按书记在本机 `gui_settings` 的 `reader.pdf_view`，
  文字模式上栏里还有一颗「看图片」换回去）。**图片模式只摆上栏那一栏**（同一个
  `.reader-bar.reader-bar-top`）—— 图片模式没有目录与书签，所以不摆下栏：
  缩放、转换成文字、**自动翻页**，以及那颗**「翻页设置」**（内核 `reader.*` 那一节 —— 正读着 PDF
  也能调节节奏，不用先切到文字那一档）。**两个平台两种弹法**：macOS 是一整块
  `NSOpenPanel`，文件与文件夹同框、都能多选；Windows / Linux 的系统对话框做不到同框
  （`IFileOpenDialog` 开 `FOS_PICKFOLDERS` 就只能选文件夹、不开就只能选文件），所以在那些
  平台上先弹一个小菜单问一句 —— **「选择电子书文件…」（多选）** / **「选择一个文件夹…」
  （内核会递归找全里面的书）**。前端按壳层的 `import_picker_modes`（`["panel"]` /
  `["files","folder"]`）决定要不要先问这一句，`src/views/Shelf.tsx` 的 `doImport(mode)`
  把选中的那一档递给 `pick_import_paths`；macOS 那条路一个字节都没变。
  导入完**这一批新书会一本本从篮口飞上架**（`components/ImportFlight.tsx` + `lib/importFlight.ts`）：
  篮口先摆出这一批的封面（像一手牌那样摊开），再一本本沿**抛物线**飞向各自的格子，
  「啪」一下弹进那格书脊；同时篮子上方贴一张**「已归位 X/N 本」**的计数器便签
  （数字是滚进去的；只有一本时不出计数器）。节奏随数量自动调：**1 本直飞、2–5 本每 300ms 一本、
  6 本以上加密到 150ms 并把单本飞行提速 20%** —— 十本也就四秒出头，不会让人干等。
  **点屏幕任意处或按 Esc 可以跳过**：剩下的书瞬间全部归位，计数器直接跳到 N/N，停留 1.5 秒后淡出。
  这一层纯粹是给眼睛看的过场（书在飞之前就已经在架上了，期间不改任何数据）；
  落在**别的屏**上的书也一样会飞：这一层先**翻到第一本新书所在的那一屏**（翻屏动画照常播），
  翻过去之后书脊就在 DOM 里了，于是照常落地；一次导入横跨好几屏时，落在更前 / 更后的那几本
  朝那一屏的方向**飞出画外**再淡出 —— 飞完你正停在新书那一屏，抬眼就是它们。
  不想要这一段的话：**设置 →「书架的样子」→「导入时让封面飞一下」**关掉即可
  （存本机 `gui_settings` 的 `shelf.import_flight`，同样不进内核）。
- **阅读页**：内核 `text` 按**行号**取文，纸页**一路向下滚**（滚到快见底就自动向内核对下一批，
  可一直读到书末）；书签是纸页右上角一枚**拟物丝带**，点一下插进当前页、再点一下拔出来
  （写入 `progress.bookmarks`，与终端按 `b` 同一份数据）。
  键盘：`↑` `↓` 翻**一行**（与终端相同，一按一行），`←` `→` / `空格` / `PgUp` `PgDn`
  滚**一屏**（`Shift+空格` 往回滚）；跳章走 `toc`，位置与书签每分钟自动写回内核（`position`），
  退出时经由 `session` 记入时长与成就。
  下栏那枚**「自动翻页」**是**免手翻**：开着之后按内核 `reader.auto_scroll_*` 的节奏自己往前走 ——
  **文字页走「屏幕行」**（一屏行的高度 ≈ 字号 × 行距），**PDF 的图片模式一次翻一页**
  （`auto_scroll_step` 调大就是「一口气翻几页」）。规矩与终端按 `a` 是**同一套**，纯逻辑单独一层
  （`src/lib/autoTurn.ts`，`npx tsx` 能逐条钉住）：**打开时先等一整拍**（不会一开就把页面抢走）、
  **你一动手（滚轮 / 按键 / 点一下）就把下一次往后推一整拍**（人在自己读时，计时器不许抢页面）、
  **连着翻 `auto_scroll_check_minutes` 分钟弹一道算术小题**确认人还在（点**哪一个**选项都算作答，
  只有一直没人理才停下 —— 与终端同一条规矩），这项填 `0` 就是不抽查。**读到书末自己停下并说一句**，
  不会停在半路一声不响。开着时左上角挂一枚「自动翻页中 · 每 5 秒 1 行」的小牌子（两栏收着也看得见，
  点它就开下栏那颗**「翻页设置」**），节奏 / 步长 / 抽查这三项都在下栏那颗**「翻页设置」**里改 ——
  它与书库里的 `settings.toml` 是**同一份**，**改完当场生效**，不用关掉书再打开。
  下栏 `Aa` 可调**正文字体（六款：默认 / 宋体 / 楷体 / 仿宋 / 圆体 / 等宽 —— 都是系统字体，
  面板里每枚胶囊自己就用那款字体写名字）、字号（20–80px）、字重（100–900）、字距（-1–6px）、
  行距（1.2–3.4 倍）与段间距（0–2.5em，段落之间多留出来的白）**，以及左右 / 上 / 下页边距
  （「上下留白一样多」可联动）。面板里每一行写的都是**大白话** ——「字多大 / 笔画多粗 /
  字与字之间 / 一行多高 / 两段之间 / 左右留白 / 上边留白 / 下边留白」，顶上还有一句
  「这几项只改这台电脑上『读起来的样子』」；换字体 / 行距 / 段间距都不碰内核，
  行号仍是唯一坐标，位置不会漂。
  旁边的**纸色**面板给纸面换配色（面板里写的是「纸的样子 / 白天或夜里 / 底色 / 字色」）：
  四套预设 —— **羊皮纸 / 护眼绿 / 深空蓝 / 代码**
  （代码主题就是点名的 `#00008b` 底 + `#ffffff` 字，像代码编辑器；它亮暗同色，
  点白天黑夜不会变样），每套都有 **白天 / 黑夜**两版，再往下可以自己挑**背景色与正文颜色**
  （自定义色盖在预设之上，可一键清除）；
  换主题时纸面、纸边、书口与正文墨色是一起变的。这些都是界面自己的状态，
  存在本机 `gui_settings` 的 `reader.prefs`（内核不认识配色与排版），
  第一次打开时亮暗跟着系统走，之后以你选的为准。
  **上下两栏默认都收着**，点**屏幕中间**才滑下来（再点一下收起，`Esc` 也可以）：
  **上栏管「这本书 / 我在哪」**（← 书架 · 书名 · 位置 · 保存位置 · 建立索引 · 快捷键提示），
  **下栏管「怎么读」**（自动翻页 · 目录 · 书签 · 光点导读 · 档位 · Aa · 纸色 · 翻页设置）——
  两栏都是浮层、不占布局：收起时书页占满一屏、提示改走屏幕下方的浮字
  （两栏呼出来时浮字自己往上让开）；跳章 / 跳书签 / 翻行后会在顶部亮一下
  「第 X/Y 行 · P%」的位置牌。`↑ ↓` 的取文请求是**串行排队**的（一次只发一份、
  连按也按顺序落地），所以不会跳段、不会丢掉上下文。
  下栏那枚**光点导读**是「跟着光读」：一位「领路的」沿当前行从左往右、**在正文下方**走 ——
  **三样任选**：**光点**（默认，一颗琥珀色小球）或者**下划线**、**波浪线**（后两样都是
  **四五个字宽的一小段线自己就是领路的** —— 就是**字底下那道线挪了个位置**：与已读行那条
  同色同粗，只比它多一伸一缩（一折之内还是先慢后快再慢，不是匀速推过去的进度条）；
  它走过的地方**迅速化掉**，所以正文里任何一刻能看到的都只有这一小段，看着就像在往前；
  英文书下约两个单词）。下划线是**墨色笔直**的一条；波浪线是**同一支笔画的波浪**
  （波长与浏览器画 wavy 下划线那支笔量着对齐，见 `src/assets/guide-wave.svg`），
  走法、宽度、步子、伸缩与下划线**完全共用一套**，只是笔迹不同。
  划过的轨迹是**字底下一条琥珀下划线**（走过的折整条亮，正在走的那折跟着领路的往前长；
  空行没有字就不画）；
  从前还有第三号**「兔子」**（书架上那只毛绒兔子跳进正文，换成像素风、一串脚印当轨迹）——
  已按用户要求去掉，老书上存过的「兔子」会自己回落成光点。
  **换成下划线 / 波浪线时那一段线自己就是轨迹**，而已读行那条**不再常驻**：刚读过时落成墨色，
  一眨眼（0.75s）就淡掉 —— 身后不留一条越积越长的下划线，「前进」的感觉就是从这儿来的。
  **空行不占时间**：三种标记遇到空行都**一步跨过去**（空行只是排版留下的缝，在那儿等一整行的
  工夫没有意义）—— 所以段与段之间不会「停顿一下」再继续；开书时恢复在那个位置、或者手滚
  停在空行上，也会当帧挪到后面第一条有字的行。
  速度按**每行停留时间**分**20 档**（**`1` 最慢 20s/行** … **`20` 最快 0.5s/行**、默认 `10` 档约 3.5s，
  与这一行有多长无关）；下栏那枚**档位**按钮点开是个小浮层：上面选**标记**（光点 / 下划线 / 波浪线），
  **再往下三枚取色器可以给这三样各自换颜色**（光点那颗小球、它划过的那条线、波浪线那一段；
  换预设主题时不影响，另有「恢复出厂色」），
  下面是一根 **1–20 的滑杆**（按钮上写着当前档位，如「10档 · 3.5s/行」），随手拖；
  按 `1–6` 是滑杆上的六个快捷档（`1` 还是最慢、`6` 还是最快）、
  按 `0`（或点下栏那枚写着当前标记的开关）开关；换档 / 换标记 / 开关时左上方淡入
  「10档 · 3.5s/行」这样的档位牌，两秒后自己淡出。
  一行走完自动换下一行；**正文快见底时导读自己接下一批**（不等你滚到底、
  也不等滚动事件）—— 所以画面会**跟着领路的往前滚**、当前行一直留在视野上方约三分之一处，
  不会走着走着滑到屏幕最下面、更不会走出视野；到书末**停下并提示一句**
  （书单报的行数比正文实际有的多时也一样收住，不会停在半路一声不响）。
  光点走到哪儿存本机（`localStorage`，按书分开：`paget.reading-guide.v1.<书 id>`），
  所以**关掉书再打开会从上次那一行接着导**；自己在屏幕上滚走、跳章或翻行之后，
  光点会跟到屏顶那一行重新开始计时（光点自己往前爬时会把当前行留在视野上方三分之一处）。
  它不碰内核的任何数据 —— 光点读到第几行只存在本机。
  书页外框是**静态**的拟物：左边一块硬皮封面、右下是书页堆叠 / 书口 —— 正文就在这张纸上滚，
  没有任何翻页动效。
- **便利贴「日记」 → 统计**（内核 `stats` 那份 `build_report`）：
  这一页是一张**手绘风的纸页** —— 稿纸的横格、左边一道页边线、角上一小条胶带与一个折角，
  数字与标题是手写体，热力图是一格格**铅笔格子**（读得越久，斜线涂得越密）；
  纸上的字**说人话**，顺着读下来是四节：**今天**（今天读了多少，离小目标还差多少）→
  **这些天**（这一周 / 这个月 / 从第一页到现在）→ **坚持**（连着读了多少天、一口气读得最久的一次、
  翻开过 / 读完 / 记下的生词 / 查过的译文 / 攒到的勋章，夜里读过还会说一句「凌晨 0~4 点读的」）→
  **每本书读了多久**（一根占比条 + 时长，书 id 收在悬停提示里）。
  数字一个都没重算：全来自内核那一份报告（措辞单独一层，见 `src/lib/statsText.ts`）。
- **便利贴「勋章」 → 成就**：内核 `achievements` —— 一整块**黑漆陈列板**，一枚一枚**金色的铁十字**
  （十字纹章：四臂向外张开、内四个角是内凹的小弧；形状是内联 SVG 的 `path`，金属感全在 CSS 的
  渐变 / 斜面 / 凹槽阴影里，没有图片）。
  **已授予**的章面镀金、章心敲着成就自己那枚符号（内核 `name` 里本来就有的那一个）、
  章底刻着解锁时间；**还没授予**的是同一尊章但**没上金**（生铁色，符号压成灰的，
  底下一条细金条报「当前 / 目标」）；**隐藏成就**章心只剩一个问号，解锁前不剧透。
  页眉那块金铭牌上是「已授予 x / y」与一条金条。
  数字仍然一个都没重算：行、进度、解锁时间全是内核 `achievements` 那一份。
  打开这一页会像 CLI 一样补记一次 `achievements_view` 事件（幂等）。
- **便利贴「调一调」 → 设置 / 数据 / 已归档**（三页合一）：**设置**是一页手绘风的**方格纸清单**
  （与「日记」那纸稿纸同一套做法，样式单独在 `styles/settings-page.css`）—— 每一项都**用大白话转述**：
  一句人话的名字（「每天读多久算达标」）、一句话说清它是干什么的、以及「现在：60 分钟」这样的人话读法；
  技术名（`stats.daily_goal_minutes`）留在一行小字里，排查时对得上 `settings.toml`。
  措辞**单独一层** `src/lib/settingsText.ts`（纯函数，能在 node 里钉住；内核以后新加的键照样显示、
  照样能改，只是不替它编说明）。
  纸上画法：开关是**铅笔方框 + 一个勾**，滑块是一道铅笔线，填空写在横线上；每一项直接写进书库，
  没有「确定 / 取消」。读写仍走内核 `config_get` / `config_set`（点号路径），并显示数据 / 正文 / 书目 /
  设置文件的位置（内核 `paths`）；
  数据用内核 `export` / `import_data`（备份迁移，只增不减）、`prune` / `clear`
  （清理失效书目 / 清空书库）。备份路径以输入框填写（一次性操作，手填最可控）。
  **这一页只列界面真的会读的那些项**（统计的小目标与联网、正文放哪儿、章节怎么认）：
  内核里只给命令行前端用的项一个都不列；「自动翻页」那几项在阅读页下栏那颗「翻页设置」里
  （正读着书的时候就能调），这一页只在原位置留一句交代。谁在哪儿露面只写在
  `src/lib/readerConfig.ts` 一处，两个页面都从它取。

- **限时模式 → 封印 → 已归档**：右键菜单的「设置限时」给一本书定一个到期日。
  这份状态和置顶一样**存在界面一侧**（`gui_settings` 的 `shelf.deadlines`，值时形如
  `{"<book_id>": "2026-10-08"}`）—— 这份状态不进内核；书脊上只标一枚 **⏳**，不显示倒计时。
  到期那天 **0 点**（`dueMoment`：到期日自己的零点过了）**书房那个每秒跳的时钟**会命中它
  （`expiredBooks`），不另设定时器。封印的顺序是 **先写 zip、再让内核 `remove`**：
  整本打包进 `<app data dir>/archived/<sha256(书名)前 8 位><4 随机字符>.zip`
  （**手写 ZIP**，deflate + 每条目 CRC-32；里面还夹着 `paget-archive.json` 元信息），
  原文件不删、只是内核记录被摘掉，书架少一格并播 `SealDissolve`（书脊**原位** 28 颗光点
  按黄金角散开）+ `SealToast`（"这本书似乎被兔子藏起来了……"）。
  **任何一步失败都只是「没封印」，不会丢数据**（半成品 zip 会被删掉）。
  「已归档」页**只读归档目录**：归档名本身看不懂是有意的，书名 / 作者 / 封印时刻 / 到期日 /
  原文件名 / 进度快照全在 zip 自己的元信息里，所以清缓存、换机器都认得出。
  点「找回」走 `archive_restore`：白名单校验归档名 → 解到**临时目录** → 内核 `import`
  → 内核 `position` 写回行号 / 百分比 / 书签 / 读完（正文没变 → book id 与封印前一致）→ 删掉 zip。

界面自己那份设置（主题、字号…）仍存 `gui_settings`，与内核的 `settings.toml` 互不干扰；
上面的每一页都不留副本 —— 数字都来自内核。


## 五个踩过的坑（都在代码里留了注释）

1. **没有 epub.js**。原计划用 epub.js 渲染，但内核存的是**转换后的 `.txt`**，
   原始 epub 不在 `~/.wreader` 里，所以 epub.js 拿不到书、也用不上 CFI。
   共用坐标只能是**行号**（与内核完全同一套），于是阅读页按行号向内核对 `text`。
   `CFI` 相关的设计保留在 `positions.cfi` 列里，留给将来"直接打开一个 epub"的功能。
2. **FTS5 的 `unicode61` 会把一整串汉字当成一个词**，`MATCH '三体'` 永远搜不到

   `三体世界就在我们眼前`。解法是入库前给每个汉字两边加空格（`db::segment_cjk`），
   查询时把整串当**短语**（`MATCH '"三体"'`），显示前再把空格去掉（`desegment_cjk`）。
   这三步缺一不可，`cargo test` 里有对应的端到端用例。
3. **`rustc 1.87` 编不动最新依赖**：`icu_* 2.3` / `darling 0.24` / `time 0.3.4x` 都要求 1.88。
   已在 `src-tauri/.cargo/config.toml` 里设 `incompatible-rust-versions = "fallback"`
   并声明 `rust-version = "1.87"`，让 cargo 在解析阶段就退回到能编的版本
   （实测把 `wry` 从 0.57 降到 0.55.1）。
4. **不用 `tauri-plugin-sql`，直接用 `sqlx`**（与最初计划不同）。
   这样 schema、中文分词、切块规则、全文查询全都能在 `cargo test` 里脱离 webview 验证，
   也不会出现"Rust 一份 schema、JS 一份 SQL"的漂移。JS 侧只调 `#[tauri::command]`。
5. **编辑器满屏 `all proc-macro server workers have exited`**（2026-10-11）：那不是代码错了 ——
   `cargo check` 一直是干净的。VS Code 的 rust-analyzer 扩展默认用**它自己随包**的 server
   （本机 `0.3.3073`，2026-10 构建），而 proc-macro server 只会从**工具链**里拿
   （`~/.rustup/.../libexec/rust-analyzer-proc-macro-srv`，1.87 → 2025-05）。两个版本对
   legacy span 协议的写法已经不一致，server 读第一个请求时就
   `assert!(id < InternId::MAX)` 崩掉（`SyntaxContextId::from_u32`），随后本 crate 里
   **每一个** `#[derive]` / `#[tauri::command]` 都被报成宏展开失败（`lib.rs` 35 条，
   `db.rs` / `archive.rs` / `core_client.rs` 也有），指向的行还各不相同 —— 这正是
   "不是代码问题"的指纹。解法是让两端**配成一对**：仓库根的 `rust-toolchain.toml`
   （`channel = "stable"` + `components = ["rust-analyzer"]`）—— 扩展只有在工作区里看到这个
   文件**且其中列了 `rust-analyzer` 组件**时，才会改用 `rustup which rust-analyzer` 那个
   server（扩展 `out/main.js` 的 `B2`/`Y2`），缺组件时 rustup 会照这一行自动装上。改完
   `Developer: Reload Window` 即可。
   换成工具链那份之后，`run()` 的 `generate_handler!` 清单上可能还剩**一条假的**
   `E0560 no such field`（同一个位置重复报很多次）：旧客户端（1.87）只走 legacy span 协议，
   对 `tauri 2.11` 这种现代宏的 span 映射是有损的。`cargo check` 干净就说明它不存在；
   想连这条也消失，得让**分析用的工具链**也跟上（`rustup update stable`，两边都换新、
   走 current 协议）—— 那会动到本仓库编译用的 rustc，先把 `rust-version = "1.87"` 那套
   MSRV 账（坑 #3）重算一遍再动。

## 测试

```bash
cd src-tauri && cargo test     # 52 项：分词 / 切块 / SQLite 端到端 / 内核位置 / 数据根 / 真 sidecar 协议
```

- `db.rs` 里的用例**不碰真实数据**：每一条都在 `std::env::temp_dir()` 里开一个临时库，跑完删掉。

## 打包

```bash
packaging/build-core.sh                              # 1) 冻结内核
npm run tauri build -- --ignore-version-mismatches   # 2) 打包成 .app / .dmg
```

**装出去之后数据在哪儿**（2026-10-14 定，覆盖安装不会再动它）：**装出去的 app** 把内核数据放在
**应用数据目录** —— macOS `~/Library/Application Support/com.paget.gui/core/`、
Windows `%LOCALAPPDATA%\com.paget.gui\core\`（`settings.toml` / `library.json` / `achievements.json` /
`novels/` / `shelf.json` 都在里面）。这个位置**只跟 app 的 identifier 有关**：覆盖安装、装新版、
把 app 挪个地方、甚至在另一台机器上打包，用户的书都还在原地。
升级第一次跑时，如果新家还空着而老位置（项目里的 `.wreader/` 或 `~/.wreader`）有数据，
壳层会把**最近写过的那一份复制**过来（项目里那份仍留给 `tauri dev`、`~/.wreader` 那份仍留给终端前端；
可重建的 `cache/` 不搬）。`tauri dev`（debug 构建）照旧用项目里的 `<repo>/.wreader/`，开发时数据不往外跑。
想强制指定就用 `WREADER_HOME`（设了就一个字节都不动）。


**第 1 步**：PyInstaller 把 `core/` 里那份 `wreader` 冻成 `src-tauri/binaries/paget-core/`，再用
`packaging/smoke_core.py` 真发一轮协议确认它能干活（不通过就别往下打）。

**第 2 步**：`tauri.conf.json` 把那个目录当**资源**发出去：

```json
"bundle": { "resources": { "binaries/paget-core": "core" } }
```

于是 macOS 上落在 `Contents/Resources/core/paget-core`（`Rust` 侧就是按
`<resource dir>/core/paget-core` 找它的，见 `core_client.rs` 的 `bundled_binary`），
Windows / Linux 上落在可执行文件旁的资源目录里。**用户机器上不用装 Python。**

### Windows：`.msi` 与 `-setup.exe`

**`.msi` 只能在 Windows 上打** —— WiX 只能在 Windows 上跑（Tauri 官方文档原话），
而且随包的内核也得在**那台 Windows 上**冻一遍（PyInstaller 不能交叉编译：
macOS 上冻出来的是 Mach-O，塞进 MSI 只会得到一个起不来的 sidecar）。所以这条路
只能在 Windows 上走。两条前置：装好 Node 与 Rust（`rustup` 在 Windows 上默认就是
`x86_64-pc-windows-msvc` 目标），以及**让那台机器能拿到内核**（见下）。然后一条命令：

```powershell
python packaging/build_windows.py          # 查环境 → npm ci → 冻内核（含烟测）→ tauri build
python packaging/build_windows.py --check   # 只查环境，不动手
```

#### 前置：那台 Windows 上得先「能拿到内核」

**源码不进安装包** —— 安装包里带的是这一步**冻出来的** `core/paget-core.exe` + `_internal/`
（约 39 MB，就是 `tauri.conf.json` 里 `bundle.resources` 那一项：`"binaries/paget-core": "core"`）。
但**冻**这一步需要一份 `wreader` 源码树，而且必须在**那台 Windows 上**冻（PyInstaller 不能交叉编译：
在 macOS 上冻出来的是 Mach-O）。两条路，挑一条：

```powershell
# ① 最省事：内核就在本仓库的 core\ 里 —— 把整个仓库 clone 下来就齐了
#    （脚本默认就找它，什么都不用设）

# ② 或者告诉脚本内核在哪（源码树放哪都行）
set PAGET_CORE_ROOT=D:\src\paget\core       # 也可以每次显式写 --core-root D:\src\paget\core

# ③ 或者干脆不落地源码：把 wreader 装进「要用来冻内核的那个 Python」
python -m pip install -e core
set PAGET_CORE_PYTHON=C:\Python313\python.exe
```

脚本按 `--core-root` > `$PAGET_CORE_ROOT` > **仓库自带的 `core\`** > 从解释器里那份
`wreader` 反推的顺序找；四条都不成时会把「试过哪些位置 + 两条出路」一次打出来（不会只丢一句
「找不到」）。`build_core.py` 与 `build_windows.py` 认同一套，两个都收 `--core-root`。

它等价于手工两步（Windows 上没有 bash，所以用 `build_core.py`，它是
`build-core.sh` 的跨平台孪生：同样的找内核 / 找解释器 / 临时目录冻结 / 烟测）：

```powershell
python packaging/build_core.py              # 1) 冻成 src-tauri/binaries/paget-core/paget-core.exe
npx tauri build --bundles msi nsis          # 2) 出安装程序
```

产物默认两个都打，落在 `src-tauri/target/release/bundle/` 下：

| 文件 | 装到哪 | 要不要管理员 |
| --- | --- | --- |
| `msi/Paget_0.1.0_x64_zh-CN.msi` | `Program Files` | **要**（MSI 走 per-machine） |
| `nsis/Paget_0.1.0_x64-setup.exe` | `%LOCALAPPDATA%` | 不要（`installMode: currentUser`） |

Windows 专属的打包配置在 **`src-tauri/tauri.windows.conf.json`** —— Tauri 只在打
Windows 时才把它合进 `tauri.conf.json`，macOS 的包一个字节都不受影响。里面定了：
只打 `msi` + `nsis`；MSI 语言 `zh-CN`（Tauri 自带的 WiX 语言表里就有它，
langId 2052 / codepage 936）；NSIS 语言 `SimpChinese`（Tauri 内置这份翻译）；
`upgradeCode` 写死（不写的话它由 `productName` 推，改个名字就会变成「另一个应用」）；
WebView2 用默认的「联网下载 bootstrapper」（要离线装就换 `offlineInstaller`，
安装包大 ~127 MB）。这个文件里写的是**严格 JSON、不放注释** —— 免得赌 CLI 有没有编译
进 JSON5 解析；每一条的理由记在 `memory-bank/activeContext.md` 的第十二轮。

**本机没有 Windows 机器时**还有一条路：`.github/workflows/windows-installer.yml` 会在 GitHub 的
`windows-latest` runner 上把同一套流程跑一遍（内核（`core/`）就在本仓库里，所以那里只 checkout
一次 —— 不需要第二个仓库、也不用配 token），产物在该次运行的 Artifacts 里（`paget-windows-installers`）。
**这条路要先把仓库推到一个 GitHub 远端** —— 2026-10-07 定的是**不推**，所以这个工作流目前只是
留在仓库里备用：真要出包，就找一台 Windows（真机或虚拟机）跑上面那条命令。

三件 Windows 上要注意的事：

- **MSI 那一步需要 Windows 的 VBSCRIPT 可选功能**（Win11 24H2 起默认被移除）：
  少了它会报 `failed to run light.exe`，去「设置 → 应用 → 可选功能 → 更多 Windows 功能」
  里勾上。（`-setup.exe` 那一路不受影响。）
- **两个包都没签名**：用户装的时候会看到 SmartScreen 警告。要消掉得买 Windows 代码
  签名证书，再配 `bundle.windows.certificateThumbprint` / `timestampUrl`。
- **这台机器上没有 Windows，所以「装完之后的样子」没人看过**：MSI / NSIS 只在这儿验到
  「配置能被 CLI 读进去 + 冻内核与脚本跑得通 + Rust 侧编译得过」。第一次真装一遍时留意
  三处：内核 sidecar 起没起来（`Resources/core/paget-core.exe`）、书架能不能读出来、
  篮子的「＋」弹不弹得出那个两选一的小菜单（Windows 上是
  `tauri-plugin-dialog` → `rfd` → `IFileOpenDialog`，这段代码只在 Windows 上跑，
  靠「不加 target 门控、让它在 macOS 上一起编译」来保它一直过类型检查）。

实测（2026-10-04，Intel macOS，rustc 1.87）：

| | |
| --- | --- |
| 冻结内核 | onedir，`paget-core` 4.6 MB + `_internal/` 共 34 MB |
| `.app` / `.dmg` | 40.7 MiB / 18.3 MiB |
| 起来后跑的是谁 | `…/Paget.app/Contents/Resources/core/paget-core`，无任何 `python` 进程 |
| 界面数据 | `~/Library/Application Support/com.paget.gui/cache.sqlite3` 里有真实书目（内核 `list` 的产物） |

两条**故意**的选择：

- **onedir 而不是 onefile**：onefile 每次启动都要把载荷解到新的临时目录、macOS 还要重扫
  一遍那个新可执行文件 —— 实测冷启动 12–24 s（onedir 1.1 s、`python -m wreader.serve` 0.7 s）。
  这笔开销落在用户开机后的第一屏上，所以发目录。
- **`--ignore-version-mismatches` 不是可选装饰**：CLI 要求 `@tauri-apps/api` 与 Rust `tauri`
  crate 的 major/minor 对齐，但本机 **rustc 只有 1.87**，`tauri` 2.12 / `tauri-plugin-opener`
  2.6 都要求 rustc 1.90 —— 只能让 Rust 侧留在 2.11.6 / 2.5.5（`.cargo/config.toml` 里那条
  `incompatible-rust-versions = "fallback"` 就是这么算出来的），而 JS 侧是 npm 按 `^2` 装出来的
  2.12.0。差一个次版本，且插件 API 根本没从 JS 用过（`plugin-opener` 只在 Rust 侧 `init`），
  所以跳过这条检查是安全的。**等 rustc ≥ 1.90**：`cargo update -p tauri -p tauri-plugin-opener`，
  这行参数就能删掉。

> 打包前先杀掉正在跑的 app：bundle 会在原地替换掉 `.app`（macOS 上不是原子操作，旧实例
> 可能读到半新半旧的文件）。
