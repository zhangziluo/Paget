# 产品背景 — Paget

## 为什么做

内核（`core/`，Python）管导入、正文、位置、统计与成就，全都在 `~/.wreader` 里。Paget 给它一个桌面界面，
目标不是「再做一个阅读器」，而是**让终端与图形界面读写同一份数据**：在终端读到第 120 行，
打开 Paget 就接着第 120 行；在 Paget 里读完一本，统计立刻反映出来。

因此最重要的一条产品判断是：**界面不持有任何权威数据**。凡是内核那里有权威值的东西
（位置、时长、书签、读完、标签…）都走内核；界面自己只留「内核不认识」的那点状态
（置顶、限时、玩具、生成的封面方案）。

## 给谁用

作者本人的机器（macOS / Intel，`rustc 1.87`）。所以不少选择是「本机可用优先」：
原生 `NSOpenPanel` 而不是跨平台对话框，随包冻结内核而不是要求用户装 Python。

## 体验目标

- **书房感**：整间屋子锁在一屏内，书放在架子上，功能藏在墙面挂件里，点开才展开成一整页，
  右上角永远有「← 返回书架」。没有标签栏 —— 书房本身就是首页。
- **数字绝对一致**：百分比、时长、字数、热力图字符全部用内核的算法，界面不"另算一遍"。
- **出错要能自己说清楚**：内核起不来时把原文错误直接显示给用户；老内核不支持的操作
  **提前禁用并说明原因**，而不是等用户点了才报错。

## 关键产品决策与理由

| 决策 | 理由 |
| --- | --- |
| **没有 epub.js，按行号取文** | 内核只保留**转换后的 `.txt`**，原始 epub 不在 `~/.wreader`，epub.js 拿不到书也用不上 CFI。共用的坐标只能是**行号**（与内核完全同一套）。`positions.cfi` 列保留给将来「直接打开一个 epub」。 |
| **SQLite 只做缓存** | 书架要秒开、全文搜索不该每次读全文。缓存可删可重建，因此不承担数据安全，schema 变了直接重建。 |
| **置顶 / 限时 / 玩具存在界面一侧** | 内核不认识这些概念。置顶与限时存本机 `gui_settings`（键 `shelf.pinned` / `shelf.deadlines`），玩偶摆法存 `localStorage`（键 `paget.shelf-toys.v1`：三只各自放不放；**不进 `gui_settings`** —— 那一格首屏第一帧就得摆对，而 `gui_settings` 是异步读的），多只之间的**间距**另存 `paget.shelf-toy-gap.v1`。 |
| **改元数据走内核，不做界面覆盖层** | 书名 / 作者 / 标签是内核 `library.json` 的权威字段：界面若另存一份「改名」就会立刻出现第二份事实（书库与书架两个名字）。所以「属性」的保存走内核 `set_meta`，只动这三个标签，正文与进度一概不碰；老内核探不到这个方法时，面板降级成只读清单并说明原因。 |
| **限时书到期「封印」而不是删除** | 到期不该真的丢书：整本打包进 `app_data_dir/archived/`，记录经内核 `remove` 摘掉，书架自然少一格。归档**自带元信息**（zip 内 `paget-archive.json`），所以清缓存、换机器都能列表与找回。 |
| **归档 ZIP 手写** | `zip` crate 不在依赖树；需要的部分（两个条目、无 ZIP64 / 加密 / 数据描述符）小到可读，也就能在 `cargo test` 里脱离 webview 验证。 |
| **导入用原生面板** | 两个平台两种弹法，但都走系统自己的对话框（不自己画一个）：**macOS** 用 `NSOpenPanel` —— 文件与文件夹同框、还能多选；**Windows / Linux** 的系统对话框做不到同框（`IFileOpenDialog` 开 `FOS_PICKFOLDERS` 就只能选文件夹），所以在那边先弹一个小菜单问「文件 / 文件夹」，用 `tauri-plugin-dialog` 弹对应的那一种。 |
| **`window.confirm` 换成页内确认条** | Tauri 的 WKWebView 没实现 `WKUIDelegate` 的 confirm：`window.confirm()` 不弹窗、恒返回 `false`，按钮会看起来「按了没反应」。 |
| **界面自己生成封面** | 没有封面图是常态。按书名算一个稳定 hash → 一组预设配色 + 书名头两个字，纯 DOM/CSS 绘制（缩放到任何尺寸都清晰），方案缓存到 `covers/<id>.json`（带版本号，改算法就 +1）。 |
| **阅读页的排版与纸面配色存在界面一侧** | **字体** / 字号 / 字重 / 字距 / 行距 / 段间距 / 页边距 / 主题 / 亮暗 / 自定义色，内核一个都不认识，所以进本机 `gui_settings` 的 `reader.prefs`。字体只用**系统自带**的六款（离线应用不引 web font），每款排几个候选名再兜一个通用族，缺字体也只是掉到通用族。预设主题（羊皮纸 / 护眼绿 / 深空蓝 / **代码** × 亮暗）是给一个好起点，**自定义背景 / 字色盖在预设之上** —— 用户自己挑的颜色优先，界面上留一句说明与「清除自定义色」回退。换主题时纸边 / 书口 / 书脊阴影由底色与墨色**重新派生**，不写死几套棕色的边。**光点导读那三样颜色**（`guideDotColor` / `guideLineColor` / `guideWaveColor`）也在这一格里：它们与字号、纸色同类 —— 都是「这台机器上读书的样子」，所以换一本书还是同一套，不跟书走。 |
| **白噪音随包九段真实录音，不联网** | 2026-10-22 起把「现场合成」换成 `src/assets/audio/` 里九段真实录音（96kbps 单声道 mp3，共 49 MB）：录音比程序化噪声更像一间真书房，代价是安装包与仓库变重。音频由 Vite `import` 成带 hash 的 url，与 JS / CSS 同一条加载链路（开发走本地静态服务、装出去走应用自己的协议），所以仍然**离线可用、不发网络请求**。 |
| **过场与封印动画全用纯 CSS** | 不加图片、不用动画库。光点方向用黄金角（137.508°）铺开，看着随机但每次重放一模一样，也不引随机数。**全项目只有两张图片资产**：木纹 `src/assets/wood-texture.svg`（当背景平铺）与波浪线那支笔 `src/assets/guide-wave.svg`（2026-10-10 加）—— 后者**只当 `mask` 用**，颜色仍由 CSS 的 `background-color` 给：径向渐变拼不出粗细均匀的波浪（试过，2–3px 尺度上是一团扇贝边），而 `background-image` 里的 SVG 是隔离渲染的、拿不到用户挑的颜色。理由见 `systemPatterns.md` 的 24e。 |
| **软件使用时间与「🙈 我不看书」只在界面一侧算** | 内核的数据全是「读书」，不知道用户停在书房 / 设置页多久。这类本机行为计时存 `paget.usage.v1` 给日记页看长累计；单次非阅读峰值只经 `usage` 事件交给成就状态，不伪装成阅读时长，也不把多次启动相加。 |
| **批量编辑逐本走内核，不做批量协议** | 管理模式的「批量改书名 / 改阅读状态 / 删除」只是对选中的书**循环调用**已有的 `set_meta` / `finish` / `remove`（内核一次只吃一本），界面不另存一份「改名」或「已读」，所以书库与下一次打开立刻看到同一份结果。逐本执行的另一个好处是**能报进度、能容错**：某一本失败继续做其余的，回执里列出失败项。改书名的文本规则（前缀 / 后缀 / 查找替换）是 `lib/shelfManage.ts` 里的纯函数，与界面无关、可断言。 |
| **排序留两条路：拖拽 + 「选中后方向键挪一位」** | 拖拽是「直接搬过去」（落点线 / 挤扁 / 跨屏都能用），选中 + 方向键是「一位一位地微调」。两条并存，是因为它们适合不同的距离：挪过两排靠拖、差一格靠键盘。三条自我约束：①**没选中时 `←` / `→` 仍是翻屏**（键盘排序不该把老手感抢走，`Esc` 放开后立刻还回去）；②**上下与左右同义** —— 书架横着排，「调顺序」就是沿着顺序走一位，不让 `↑` `↓` 变成猜不透的「换排」；③**隔板挪的是整个区**（两头锚点一起走，区里管着哪几本不变；拖单块板才是改边界），贴到书架那一头就**挪不动**（硬挪会把区挤出去而缩水）。判定与边界都是 `lib/shelfManage.ts` 的纯函数（`nudgeStep` / `shiftBook` / `shiftDivider`），能一条条钉住。 |
| **区名标签一区一枚** | 一个区只在**最靠下那本**（区内最后一本）下面贴一条，不是每本一枚：架上清爽，读到这一枚就知道这一区到这儿为止（原本「每本一枚」的方案信息重复、挡板被白条切碎）。空区（两板并排、还没圈到书）没有书可贴，名字才落回板上。哪一本算尾由 `regionTails` 算，且**按可见书目算** —— 搜索过滤时落在剩下那几本里最靠下的一本，不会整区没了名字。 |

## 兼容性承诺

- 与内核共用 `~/.wreader`：界面只经 RPC 读写，从不直接碰这些文件。
- **较新的内核方法要能缺席**：`remove` / `finish` 是 2026-10-04 才加进 `wreader/serve.py` 的。
  界面启动时用一个**不可能存在的 book id** 各探一次（`unknown method` = 不认识，
  `unknown book id` = 认识；探针零副作用），探不到就把菜单项**禁用**并说明原因。
- **随包内核与源码树行为一致**：`packaging/paget-core.spec` 刻意**保留 `requests`**
  （地理成就用），刻意**排除 `rich` / `curses`**（那是终端前端的东西），
  也不复制 `dist-info`（否则会误触发「可编辑安装」成就）。
